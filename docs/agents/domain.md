# Domain documentation

This repository uses a single context.

- Before exploring domain behavior, read the root GLOSSARY.md.
- Before proposing architectural changes, read relevant docs/adr/ records.
- Use glossary terms consistently in specifications, issues, and tests.
- Surface conflicts with ADRs instead of silently overriding them.
- If a referenced domain document is absent, proceed without creating placeholder documentation; record terms and decisions when resolved.
